> **SUPERSEDED (2026-06-27).** The demo pivoted to a **live mujoco-wasm + onnxruntime-web
> engine** that renders the *simulated* state — there is no precomputed full-body pose
> playback. The live policy consumes the compact **reference command** instead — see
> [`REFERENCE_STREAM.md`](REFERENCE_STREAM.md). This spec is retained only as a possible
> starting point for the parked no-WASM playback fallback (backlog wbc-mjlab-ukl).

The contract between the **exporter** (`wbc-mjlab` `export-web-policy`, issue wbc-mjlab-5uw)
and the **playback renderer** (issue wbc-mjlab-3ne). Both MUST implement exactly this.

A clip is a per-frame stream of **body world poses** for the full robot, so the renderer can
pose every GLB body node directly (no in-browser physics — that's M2).

## Body order — the root contract

Pose order and body count come from `public/robots/<robot>/g1.bodies.json` (produced with the
GLB by wbc-mjlab-9as). For G1: **31 bodies**, index 0 = `world` (no mesh), indices 1–30 carry
visual meshes. The `.bin` pose at body-index `b` corresponds to `bodies[b]` in that file.

## `.bin` file — `clips/<clipId>.bin`

- Raw **little-endian Float32**, no header.
- **Frame-major** layout. For each frame `f` in `[0, frames)`, for each body `b` in `[0, B)`
  (B = `bodies` count, in `g1.bodies.json` order), **7 floats**:
  ```
  posX, posY, posZ,  quatW, quatX, quatY, quatZ
  ```
  Position in **meters**, **MuJoCo Z-up world frame** (`data.xpos`). Quaternion is
  **`(w, x, y, z)`**, unit-norm (`data.xquat`).
- Total floats = `frames * B * 7`; bytes = `frames * B * 7 * 4`.
- Body index 0 (`world`) is included (emit zeros / identity quat `1,0,0,0`); the renderer
  skips it. (Including it keeps `b == MuJoCo body id`.)

## `clips/index.json`

```json
{
  "schema": "wbc_web_clips_v1",
  "robot": "g1",
  "bodies": 31,
  "fps": 50,
  "clips": [
    { "id": "walk1_subject1", "name": "Walk", "file": "walk1_subject1.bin",
      "frames": 13065, "durationSec": 261.3, "tags": ["walk", "locomotion"] }
  ]
}
```
- `bodies` MUST equal the count in `g1.bodies.json`. `fps` is the playback rate (50).
- `file` is relative to the `clips/` dir. `id` is referenced by the manifest's
  `defaultClip` / `artifacts.clips.default`.

## Renderer responsibilities (3ne)

- Fetch `.bin` as `ArrayBuffer` → `Float32Array`; slice `frames × B × 7`.
- Per frame, set each body node `b` (1–30) world transform from its 7 floats.
- **Frame conversion:** apply a single root rotation to map MuJoCo **Z-up → three.js Y-up**
  (rotate −90° about X), and reorder quat `(w,x,y,z)` → three.js `(x,y,z,w)`.
- The shipped robot mesh is **meshopt-compressed** (`g1.meshopt.glb`) — wire `MeshoptDecoder`
  into `GLTFLoader`.

## Source semantics

M1 playback renders the **reference motion** of each clip (kinematic targets), generated by FK
over the clip's per-frame qpos — the same "one policy, many clips" library shown in the gallery.
The M2 live engine renders the policy's *achieved* motion instead, reusing the same renderer.
